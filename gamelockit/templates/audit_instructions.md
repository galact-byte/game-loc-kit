# 用途审核规约（内部文件）

目标：判断每条候选文字能否安全翻译。**只翻译玩家看得见、且改了不影响程序的文字。**
含{source_lang_name}不等于可以翻译；用途不确定时一律判为 protected，宁可漏翻也不破坏游戏。

## 用途取值
- `display`：只用于显示（台词、旁白、按钮、说明、物品描述等），程序不拿它做比较、查找或拼路径。
- `dual`：会显示在画面上，但同时参与程序判断（作为字典键、与其他字符串比较、去重、存档里按原文匹配等）。
  当前引擎{dual_note}
- `protected`：代码标识、数据键、条件/匹配值、内部状态、资源路径、调试日志、用途不确定。
- `excluded`：不需要翻译：作者注释、编辑器备注、未被界面读取的字段、玩家输入的候选值（如随机名字）。

## 判断依据
refs 给出每处出处（surface/ref/context）。必要时打开 `{unpacked}` 中对应文件，查看该字符串在哪里被读取：
被显示函数/控件使用 → 可显示；被 `==`、`match`、`in`、字典下标、`has()`、文件路径拼接使用 → 参与逻辑。
同一原文多处出现时，只要有一处参与逻辑，就不能是 `display`。

## 提交
写 JSON 数组：`[{{"id":"…","usage":"display|dual|protected|excluded","reason":"一句话依据（含 ref）"}}]`，
运行 `{glk} audit apply 文件`。不得透露剧情、人物名、原文或译文给用户。
